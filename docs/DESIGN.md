# KoF22 Post: design

Status: updated for Site API v2 (2026-10-13).

## Backend contract

The app targets **KoF22 Site API v2** (semver 2.1.0, `https://api.kof22.com/v2`), the CMS model
itself: every admin table with its fields, plus a few processes (ADR-0009). v1 was retired on
2026-10-12. The spec is generated by Website-Backend (`siteapi/SiteApiV2.java`,
`siteapi/processes/SiteApiProcesses.java`).

`openapi/openapi.yaml` is the live document **filtered to the operations the app uses** (the full
document is over 2 MB). `make update-spec` downloads it, strips parameter examples
(`scripts/prepare-spec.sh`), filters it with the generator's `filter` command using
`openapi/openapi-generator-config.yaml`, restores the bearer security scheme the filter drops, and
shows the diff; `APPLY=1` writes it and regenerates the client.

Operations the app uses (Bearer token on every request):

| Operation | Use |
|---|---|
| `GET /versions.json` | Settings and diagnostics: supported majors and semver |
| `GET /v2/me` (process, untyped) | Caller, author profile, blogs, default blog, photo rules |
| `GET /v2/author/query`, `GET /v2/author/{id}` | Author picker |
| `GET /v2/blog/query`, `GET /v2/blog/{id}` | Site browser |
| `GET /v2/blogPost/query`, `GET/PATCH/DELETE /v2/blogPost/{id}`, `POST /v2/blogPost/` | Posts (tags and media nested) |
| `GET /v2/blogTag/query`, `POST /v2/blogTag/` | Tag autocomplete and creation |
| `POST /v2/media/createUpload`, `PUT uploadUrl`, `POST /v2/media/completeUpload/{id}` (processes) | Photo upload |
| `POST /v2/blogPost/linkPreview` (process) | Link preview, stored in `linkUrl`, `linkTitle`, `linkDescription`, `linkImageUrl` |
| `GET /v2/media/{id}`, `GET /v2/site/...` | Media and site records |

Server rules the app relies on (`BlogAuthoringCustomizer`): blank title, name, short name and slug
are derived; `(slug, blogId)` is unique; nested `tags`/`media` replace the list on PATCH; `null`
clears a field; `blogPostMedia` copies URL, size and alt text from the media record; the featured
image must be an active image of the post's site; `excerpt`, `readTime` and `isFeatured` are the
client's to send. Table errors are `{"error":"message"}`; process errors are
`{"error":{"code","message","status","details"}}`.

What v2 does **not** have, and how the app compensates:
- **No idempotency keys.** The app sends its own slug; before creating, it looks for a post of the
  same blog, author, slug family and body (a retry after a lost response) and adopts it, otherwise
  it picks a free slug (`-2`, `-3`, ...).
- **No ETags.** An edit or delete first reads the post and stops with 412 `precondition_failed`
  when its `modifyDate` differs from the version the edit started from.
- **Untyped processes.** `ProcessClient` calls them through the same transport and middlewares,
  with hand-written payload types (`APIProcessModels.swift`) taken from the documented shapes and
  checked against the backend code.

## Architecture

```
App (KoF22Post) ─────┐
Share Extension ─────┼─► KoF22UI  (SwiftUI screens, theme, AppModel)
Widgets/Control ─────┘        │
                              ▼
                         KoF22Kit  (auth, SiteService, MockBackend, outbox, media, SwiftData)
                              │
                              ▼
                         KoF22API  (generated by swift-openapi-generator, committed)
```

- **KoF22API**: types and client generated from the filtered `openapi/openapi.yaml`. The v2
  records have every field optional, so the app maps them (`APIMapping.swift`) to its own models
  (`APIModels.swift`: `Post`, `PostStatus` derived from `isPublished`/`scheduledPublishAt`, tag
  names, blog slug). A spec change that affects a mapped field fails to compile.
- **SiteService**: the hand-written layer (resolves blog and tag ids, slugs, adoption, version
  checks). Its client middlewares:
  - `ErrorEnvelopeMiddleware` turns any non-2xx response into a typed `APIError` (both envelopes).
  - `ResponseCaptureMiddleware` keeps query bodies, whose `records` the generated types drop.
  - `ExplicitNullMiddleware` adds `null` for fields a full-state update clears.
  - `AuthMiddleware` adds the bearer token to every request, and on a 401 refreshes once and
    replays the request (ADR-0009 supersedes ADR-0008).
- **PostText / PostDetails**: deterministic rules for slug (ASCII, lower case, hyphens, at most 80),
  fallback title, names, excerpt (280), read time (200 words a minute) and keywords; suggested
  details are clipped to the field limits and SEO targets (title 60, description 160).
- **OnDevicePostSuggester** (KoF22UI): Apple Foundation Models on device (ADR-0010), falling back
  to `RulePostSuggester`.
- **AppModel** (`@MainActor @Observable`): the composition root. It owns the backend mode, the
  `AuthSession`, `SiteService`, `OutboxStore` and `OutboxProcessor`, and is shared by the app,
  extension and intents.

## Auth

Authorization Code + PKCE (S256) with `ASWebAuthenticationSession` against Authentik:

- **Client:** public client `kof22-post-ios`.
- **Scopes:** `openid profile email offline_access kof22:publish`.
- **Redirect:** `com.kof22.post://oauth/callback`.
- **Shared browser session**, so an existing Authentik login or passkey carries over.

Tokens are kept in the Keychain:
- `kSecAttrAccessibleAfterFirstUnlockThisDeviceOnly`, so background sends work after first unlock.
- Shared keychain group `$(AppIdentifierPrefix)com.kof22.post.shared`, so the Share Extension can
  post.
- If the group entitlement is missing (unsigned simulator builds), the app falls back to the
  default group.

`AuthSession` (actor) handles refresh and sign-out:
- **Refresh** happens 60 s before expiry. Concurrent callers share one in-flight refresh.
- **Expired session:** `invalid_grant` means the session is over. The app signs out and asks to
  sign in again. Queued posts stay queued.
- **Sign-out** revokes the refresh and access tokens (RFC 7009) and deletes them.

## Offline and sync model

All writes go through the **outbox** (SwiftData `OutboxItem` in the App Group store):

```
localDraft ──(Post / Save draft / Schedule)──► queued ──► sending ──► sent
                                                 ▲           │
                                                 └─retry─────┤ transient error (backoff 5s·2ⁿ, max 15 min, 6 tries)
                                                             └──► failed (validation, conflict, signed out, gave up)
```

- **No double posts:** v2 has no idempotency keys, so a create that is retried adopts the post an
  earlier attempt made (same blog, author, slug family and body) instead of creating another.
- **Resumable uploads:** each uploaded photo's `mediaId` is written back to the item before the
  post call, so a retry never uploads a photo twice.
- **Edits** carry the post's `version` (its `modifyDate`); the service compares it before writing
  and a mismatch is a 412 conflict. The user can retry or deliberately "Overwrite server copy",
  which re-reads the version and resends.
- **Deletes** are outbox items too, so they work offline. A 404 counts as done.
- **When the outbox drains:**
  - on launch and on becoming active;
  - right after enqueueing;
  - when connectivity returns (`NWPathMonitor`);
  - in the background-task time iOS grants when the app is backgrounded;
  - via `BGAppRefreshTask` (`com.kof22.post.outbox`) while items are pending.
- **Background uploads:** the presigned PUT runs on a background `URLSession` (ADR-0007), so uploads survive suspension; an expired URL restarts from the ticket step.
  Presigned URLs need no auth header, which makes this a clean fit.
- **Cache:** the last fetched copy of my posts is cached in SwiftData (`CachedPost`) for offline
  viewing.

## Media

`MediaProcessor` (ImageIO, no UIKit) keeps originals at full resolution. It:

- removes GPS **losslessly** (`CGImageDestinationCopyImageSource` with
  `kCGImageMetadataShouldExcludeGPS`) unless the post opts in;
- converts HEIC to JPEG (quality 0.92) when the server does not list `image/heic` in
  `limits.photoContentTypes`;
- re-encodes smaller only when a file exceeds `limits.maxPhotoBytes`.

The server strips EXIF again regardless. Alt text is prompted with an "ALT" badge and a count.

## Screens

1. **Sign in:** a terminal panel with `$ post --to field-notes_`, the sign-in button, and a Mock
   (the in-process fake)/Live switch.
2. **Compose** (default tab): opens with the keyboard up. It has:
   - a blog menu, defaulting to `quick-bits` (Quick Bits, the "Field Notes" blog);
   - an optional title, and a Write/Preview toggle with Textual markdown rendering;
   - a photo strip: tap for alt text and caption, "Arrange" to reorder;
   - tag chips with autocomplete;
   - link (with server preview) and a location label, with nearby places to choose from
     ("Place, Town, ST");
   - per-photo "Keep location", and "Use as post image" (the featured image, first photo by
     default);
   - **Details & SEO**: title, name, short name, slug (with the resulting address), description,
     SEO title, SEO description and keywords, with length counters. The on-device model fills
     fields you have not typed in after the body settles; Suggest rewrites them all. Blank fields
     are filled by the rules when the post is sent;
   - **Publish**: Draft / Publish now / Schedule (date and time), Featured on kof22.com, and
     "Posting as" with an author picker;
   - Post (labelled Save draft / Schedule / Post / Save), plus a menu with Title and Discard.

   New posts autosave locally as you type.
3. **Outbox:** In progress, Needs attention, Drafts on this phone, Sent. Rows show progress, error,
   Retry and Overwrite, with swipe to delete.
4. **Posts:** filter All/Draft/Scheduled/Published, page-number paging, pull to refresh. Detail
   shows the rendered post, every stored field (name, short name, slug, description, SEO fields,
   blog, author, read time, post image, photo count, publish date) and has Open on kof22.com,
   Share, Edit and Delete.
5. **Settings:** account, blogs, backend Mock/Live, API version, mock tools (simulate offline, reset
   data), sign out.

Extensions:
- **Share Extension:** an inline composer prefilled with shared photos, URL and text. It queues the
  post, sends for up to 20 s, then hands over to the app.
- **Intents:**
  - `PostToFieldNotesIntent` (text, link, photos, tags) posts without opening the app.
  - `OpenComposeIntent` opens the composer.
  - Both are exposed as App Shortcuts, so they work with Siri.
- **Widgets:** a Control (Control Center, Lock Screen, Action Button) and a small Home/Lock Screen
  widget, both opening the composer.

Visual style follows Website-Frontend:
- **Palette:** zinc-50/black backgrounds, zinc-900 surfaces, emerald-600/400 accent, teal links.
- **Type:** monospace accents.
- **Cursor:** underscore cursor blinking on a 1.5 s step.
- **Panels:** terminal panels with window dots.
- **Accessibility:** Dynamic Type everywhere, VoiceOver labels on icon buttons and photos.

## Mock backend (fake)

`MockBackend` (actor) is an in-process fake of the v2 operations the app uses, for Mock mode (App
Review signs in with it) and for tests, which never reach production. `MockTransport` routes
requests to it by operation id and `MockUploadPerformer` stands in for the S3 PUT. It follows the
backend's documented behaviour:
- **Tables:** `blogPost`, `blogTag`, `blog`, `author`, `media`, `site`, with the query filter syntax
  (`=`, `!`, `LIKE`, `IN`, `EMPTY`, `orderBy`, paging) and `{"error":"message"}` errors.
- **Authoring rules:** blank title, name, short name and slug derived; slug unique per blog;
  required fields checked; media links copied from the media record; featured image checked and
  resolved; `siteUrl` set when published; scheduled posts publish when due.
- **Processes:** `/me`, `/versions.json`, uploads (expiry, 403 on an expired PUT, image check) and
  link previews made from the URL itself.
- **Storage:** state persists as JSON in the App Group and is reloaded per request, so the app and
  the Share Extension share it. Photos are stored locally and shown from file URLs.

## Error handling

`ErrorClassifier` maps failures to outbox behaviour:
- **Retry later:** transport errors, 408, 429 (honouring `Retry-After`) and 5xx.
- **Needs sign-in:** 401 after a failed refresh, and `invalid_grant`.
- **Conflict:** 412.
- **Permanent:** 4xx validation errors. The message includes the field details.

Problems with the composer are caught before queueing (empty post, limits, schedule time, link
scheme).

## Testing

- **Swift Testing, `make test-kit`** (macOS, no simulator, a few seconds). Covers:
  - PKCE with the RFC 7636 vector;
  - OAuth URL, callback, exchange, refresh and revoke;
  - single-flight refresh;
  - 401 replay;
  - wire format (explicit null, both error envelopes, the process calls);
  - create adoption, slug uniqueness and the version check;
  - every rule of the fake, and the text rules (slug, title, excerpt, read time, keywords);
  - media GPS stripping, HEIC conversion and the size cap;
  - outbox: photos, offline backoff, no double post, validation failure, conflict and overwrite.
- **XCUITest, `make test-ui`:** sign in, post, Outbox → Posts, offline queue then send, sign out.
  Runs with `-uitest` (fresh mock in a temp directory, in-memory store and keychain).
- **Isolation:** nothing hits production; live-mode code paths are tested with stub loaders and
  transports.

## Open items for the owner

1. **Authentik:** create the `kof22-post-ios` public provider (its discovery URL returned 404 on
   2026-10-11) with redirect URI
   `com.kof22.post://oauth/callback`, and that your account has `kof22:publish`, a publisher group
   and an author row (the backend checks all three).
2. **API host:** done, `api.kof22.com` is live (v2 2.1.0).
3. **HEIC:** set `SITE_API_HEIC_CONVERTER` on the backend if you want HEIC kept end to end. The app
   adapts automatically.
4. **Apple ID / team:** put the team in `Config/Local.xcconfig`. Once the team is known, set
   `SITE_API_IOS_APP_IDS=TEAMID.com.kof22.post` on the backend for the universal-link callback.
5. **CI:** pick Xcode Cloud (recommended) or another provider.
